# Between Us 🌻

A private, mobile-first space where exactly two people share links (Instagram, Spotify, YouTube, anything) with a note, and organise them into collections.

**Stack:** Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · PostgreSQL · Prisma 7 · Better Auth · Zod · Lucide · Vitest

## Setup

```bash
npm install                 # also runs `prisma generate`
cp .env.example .env        # then fill it in (see below)
```

### Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | yes | Postgres URL used by the app. On Supabase: the **Transaction pooler** (port 6543). |
| `DIRECT_URL` | no | URL used only by `prisma migrate` (Supabase **Session pooler**, port 5432, or direct). Falls back to `DATABASE_URL`. |
| `BETTER_AUTH_SECRET` | yes | Session signing secret — `openssl rand -base64 32` |
| `BETTER_AUTH_URL` | yes | Public origin (`http://localhost:3000`, or your production URL). Sign-in fails with "Invalid origin" if you open the app from a different origin. |
| `MARTINHA_PASSWORD`, `RICARDO_PASSWORD`, `SPACE_NAME` | no | Provisioning only; leave passwords empty to get random ones. Don't set on Vercel. |
| `TEST_DATABASE_URL` | no | Overrides the test DB (default `…/betweenus_test` on the local Docker DB) |

### Database

Local Postgres via Docker:

```bash
docker run -d --name between-us-db -e POSTGRES_USER=betweenus -e POSTGRES_PASSWORD=betweenus -e POSTGRES_DB=betweenus -p 54329:5432 postgres:17-alpine
```

Migrations:

```bash
npx prisma migrate dev      # development: apply + create new migrations
npm run db:migrate          # production/CI: apply existing migrations only
```

### Account provisioning

There is no sign-up. Two accounts exist, **martinha** and **ricardo**, and they sign in with username + password:

```bash
npm run provision             # creates missing users, prints random passwords ONCE
npm run provision -- --reset  # issues new passwords for existing users (e.g. a forgotten one)
```

Passwords are generated by the script, hashed with scrypt (Better Auth) before they reach the database, and never stored in plain text or in the repo. Copy them from the terminal into a password manager. The script refuses to add anyone beyond those two to the Space. Better Auth needs an email column, so each user gets an internal `username@betweenus.local` that is never shown or used.

## Deploying to Vercel + Supabase

1. **Supabase:** create a project. In *Project Settings → Database → Connection string* copy:
   - **Transaction pooler** (port 6543) → `DATABASE_URL`
   - **Session pooler** (port 5432) → `DIRECT_URL` (the direct `db.*.supabase.co` host is IPv6-only unless you have the IPv4 add-on)
   Append `?sslmode=no-verify` to both (encrypted connection; Supabase's CA isn't in Node's trust store — to fully verify, download Supabase's CA cert and use `sslmode=verify-full` with `sslrootcert`).
2. **Migrate + provision from your machine** (one time, and after each schema change):
   ```bash
   DATABASE_URL="<session pooler url>" npm run db:migrate
   DATABASE_URL="<session pooler url>" npm run provision
   ```
   The provision output contains the two passwords — save them.
3. **Vercel:** import the repo and set `DATABASE_URL`, `DIRECT_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (your production URL, e.g. `https://between-us.vercel.app`). Framework preset: Next.js; the build command (`prisma generate && next build`) is already in `package.json`.
4. Deploy. Preview deployments sign in on their own `*.vercel.app` origin automatically; they share the same database, so use a separate Supabase project if you want isolated previews.

Notes: the app opens at most 3 DB connections per serverless instance on Vercel (`src/lib/db.ts`) so the pooler isn't exhausted. Migrations are never run during the build.

## Architecture

```
src/
  app/(auth)/login        login screen (client form → Better Auth)
  app/(app)/…             home, share, collections, collections/[id], profile — auth-gated by layout
  app/api/…               REST route handlers (thin: auth + Zod + service call)
  components/ui           Button, Input/Textarea, Avatar, Badge, Skeleton, Dialog/ConfirmDialog, Logo
  components/…            feed, sharing, collections, navigation
  modules/auth/session.ts getViewer()/requireViewer() — the only source of userId/spaceId
  modules/items           resolve-platform (URL validation + embeds), schemas, service
  modules/collections     schemas, service
  modules/profile         schemas, service
  lib/                    db (Prisma + pg adapter), auth (Better Auth), api helper, utils
  proxy.ts                optimistic redirect to /login when no session cookie
prisma/schema.prisma      Space, User, SharedItem, Collection, CollectionItem + Better Auth tables
scripts/provision.ts      creates the Space and the two accounts (random passwords)
tests/                    Vitest: unit (URL resolver, schemas) + integration against Postgres
```

Key decisions:

- **Authorization lives in the service layer.** Every service function takes a `Viewer` (`{ userId, spaceId }`) built from the session, and every query filters by `spaceId`. Client-sent `userId`/`spaceId` are never read (Zod strips them). `proxy.ts` is only a UX redirect, not a security boundary.
- **Better Auth shares the `User` table.** `image` is mapped to `avatarUrl`; `spaceId` is a server-only additional field (`input: false`), so it can't be set via the auth API. Email sign-up is disabled.
- **Previews never fetch user URLs server-side** (no SSRF surface). Embeds are derived from the URL string: YouTube → thumbnail facade + `youtube-nocookie` iframe on click; Spotify → official embed iframe; Instagram posts/reels → the official `/embed` page; everything else (stories, profiles, unknown sites, malformed IDs) → a link card. Hostnames are matched exactly, so `youtube.com.evil.test` is "Other".
- **Collections are many-to-many** via `CollectionItem` (composite PK). Deleting a collection cascades only to its associations; deleting a shared item removes it from all collections. Either member can edit/delete any collection; only the author can delete their own share.
- **Feed pagination** is cursor-based (`createdAt desc, id desc`, indexed per Space), loaded on scroll with a "Load more" fallback.
- **Server Components by default**; client components only for forms, dialogs, feed paging and preview interaction. Mutations go through the REST API and then `router.refresh()`.

## Known limitations

- Avatars are https image URLs (no uploads — no blob storage in the MVP).
- "Other" links show domain + URL only; titles/thumbnails would need server-side fetching, deliberately skipped.
- Instagram embeds can still show Instagram's own "unavailable" frame for private/removed posts; we can't detect that cross-origin. "Open original" is always available.
- The "Add items" dialog on a collection lists the 50 most recent shares.
